# 自動実装モード

このコマンドは、要件を受け取ってから完了まで自動的に実行します。

## ワークフロー

### 1. 実装方針の提示
- 要件を分析し、実装すべき内容を整理
- 必ず `docs/baseball-project-architecture.md` を読み込んで既存のアーキテクチャパターンを確認
- 必ず `docs/coding-standards.md` を読み込んで既存のコーディング規約に従う
- 技術選択・アーキテクチャ・ファイル構成を提案
- 実装手順・ポイントを説明
- **ユーザーの承認を得る（y/n）**

### 2. 自動実行（承認後）
承認を得たら、以下を**自動的に**実行してください：

#### 2.1 実装
- TodoWriteツールでタスクを管理
- コーディング規約に従って実装
- 適切なコメントを追加
- セキュリティ脆弱性に注意

#### 2.2 リファクタリング
- コードの重複を排除
- 可読性の向上
- パフォーマンスの最適化（必要に応じて）

#### 2.3 簡易テスト
以下のいずれかを実行：
- Vueコンポーネント: `npm run dev` で動作確認可能であることを確認
- Javaコード: `./mvnw compile` でコンパイル確認
- 必要に応じてユニットテストを実行

#### 2.4 セルフレビュー
以下の観点でレビュー：
- [ ] コーディング規約に準拠しているか
- [ ] アーキテクチャパターンと整合性があるか
- [ ] セキュリティ脆弱性がないか（XSS、SQLインジェクション等）
- [ ] エラーハンドリングが適切か
- [ ] レスポンシブデザインに対応しているか（UI変更の場合）
- [ ] パフォーマンスに問題がないか

### 3. 完了報告
以下を含むサマリーを報告：
- 変更ファイル一覧
- 主な変更内容
- テスト結果
- レビュー結果
- 次のステップの提案（あれば）

## コマンド比較

| 項目 | /implement | /auto-implement | /team |
|------|-----------|----------------|-------|
| 人数 | 1人 | 1人 | 10人 |
| 設計 | ❌ | ✅ | ✅ PM+アーキテクト |
| 実装 | ✅ | ✅ | ✅ BE+FE並列 |
| レビュー | ❌ | ✅ セルフ | ✅ セキュリティ+鬼レビュー+QA |
| テスト | ❌ | ✅ 簡易 | ✅ 専任QA |
| 推奨場面 | 小さな変更 | 中規模の機能開発 | セキュリティ重要・高品質が必要 |

## 重要事項

- **途中確認が必要な場合**: 重大な問題、技術的な選択肢、要件の曖昧さが発見された場合のみユーザーに確認を取る
- **エラー発生時**: エラーが発生した場合は即座に報告し、対処方法を提案
- **より高品質を求める場合**: `/team` で専門家チームによる開発を推奨
- **言語**: 思考は英語、アウトプットは日本語
