# コードレビュー

指定されたファイルまたは最近の変更に対してコードレビューを実行します。

## レビュー観点

### 1. コーディング規約
- `docs/coding-standards.md` の規約に準拠しているか確認
- 命名規則の一貫性
- インデント、フォーマットの統一

### 2. アーキテクチャ整合性
- `docs/baseball-project-architecture.md` のパターンに従っているか
- 責務の分離が適切か
- レイヤー構造が正しいか

### 3. セキュリティ
- XSS、SQLインジェクション、コマンドインジェクション等の脆弱性がないか
- 入力値のバリデーションが適切か
- 機密情報（パスワード、APIキー）がハードコードされていないか

### 4. エラーハンドリング
- 例外処理が適切か
- ユーザーへのエラーメッセージが適切か
- ログ出力が適切か

### 5. パフォーマンス
- N+1問題がないか
- 不要なループ、処理がないか
- キャッシュの活用

### 6. UI/UX（フロントエンド）
- レスポンシブデザイン対応
- アクセシビリティ
- ユーザービリティ

### 7. テスタビリティ
- テストしやすい構造か
- 依存関係が適切か

### 8. 保守性
- コメントが適切か
- コードの可読性
- 重複コードがないか

## 出力形式

レビュー結果を以下の形式で出力：

```markdown
## レビュー対象
- ファイル名:行数

## 良い点
- ✅ ポイント1
- ✅ ポイント2

## 改善提案
- ⚠️ 問題点1
  - 理由
  - 改善案
- ⚠️ 問題点2
  - 理由
  - 改善案

## 重大な問題
- 🚨 問題（あれば）

## 総評
全体的な評価とコメント
```

## 使用方法

### 特定ファイルをレビュー
```
/review src/main/java/com/example/baseball/service/AtBatResultService.java
```

### 最近の変更をレビュー
```
/review
```

### 複数ファイルをレビュー
```
/review vue-project/src/components/SearchBaseball.vue vue-project/src/components/AppFooter.vue
```

## 関連コマンド

| やりたいこと | コマンド |
|-------------|---------|
| コードレビューだけ | `/review`（これ） |
| 実装+セルフレビュー | `/auto-implement` |
| セキュリティ+品質+テストの3軸レビュー | `/team` |

## 注意事項

- レビューは建設的に、具体的な改善案を提示
- 重大な問題がある場合は明確に指摘
- 良い点も積極的に評価
- より多角的なレビューが必要な場合は `/team` を使用（セキュリティ審査官+鬼レビュアー+QAの3人並列レビュー）
