# ドキュメント作成コマンド

プロジェクトの各種ドキュメントを自動生成・更新します。

## ドキュメント種類

### 1. API ドキュメント
**内容:**
- エンドポイント一覧
- HTTPメソッド
- リクエストパラメータ
- レスポンス形式
- エラーコード
- 使用例

**生成方法:**
Controllerファイルを解析して自動生成

**保存先:** `docs/api-documentation.md`

---

### 2. README / セットアップガイド
**内容:**
- プロジェクト概要
- 機能一覧
- 技術スタック
- 環境構築手順
- 起動方法
- デプロイ方法

**保存先:** `README.md` または `docs/setup-guide.md`

---

### 3. アーキテクチャドキュメント
**内容:**
- システム構成図
- レイヤー構成
- データフロー
- 技術選定理由
- ディレクトリ構成

**保存先:** `docs/baseball-project-architecture.md`（既存更新）

---

### 4. 機能仕様書
**内容:**
- 機能一覧
- 画面仕様
- ビジネスロジック
- バリデーションルール
- データモデル

**保存先:** `docs/feature-specifications.md`

---

### 5. 運用ドキュメント
**内容:**
- デプロイ手順
- 環境変数設定
- トラブルシューティング
- 監視項目
- バックアップ手順

**保存先:** `docs/operations-guide.md`

---

### 6. コーディング規約
**内容:**
- コーディングスタイル
- 命名規則
- ベストプラクティス
- セキュリティガイドライン

**保存先:** `docs/coding-standards.md`（既存更新）

---

### 7. 既存コードのドキュメント化
**内容:**
- クラス/メソッドの説明
- パラメータ説明
- 使用例
- 注意事項

**形式:** Markdown または JavaDoc/JSDoc スタイル

---

### 8. 変更履歴（CHANGELOG）
**内容:**
- バージョンごとの変更内容
- 追加機能
- 修正内容
- 破壊的変更

**保存先:** `CHANGELOG.md`

---

## 実行フロー

### 1. ドキュメント種類の確認
ユーザーが作成したいドキュメントを特定

### 2. 情報収集
- 既存ファイルの読み込み
- `docs/baseball-project-architecture.md` の参照
- `docs/coding-standards.md` の参照
- コードベースの解析（必要に応じて）

### 3. ドキュメント生成
以下の形式で生成：

```markdown
# [ドキュメント名]

## 概要
[簡潔な説明]

## 目次
- セクション1
- セクション2

## [メインコンテンツ]
...

## 更新履歴
- YYYY-MM-DD: 初版作成
```

### 4. 保存確認
- 保存先を提示
- ユーザー承認（y/n）
- 承認後、ファイルに保存

### 5. 完了報告
- 作成したドキュメントのパス
- 主な内容
- 次のステップ

## ドキュメント生成の原則

### 1. 正確性
- コードベースの実態を反映
- 古い情報を含めない
- 検証可能な情報のみ記載

### 2. 完全性
- 必要な情報を網羅
- 手順は具体的に記載
- 例を含める

### 3. 可読性
- 明確な見出し構造
- 簡潔な文章
- コードサンプル付き
- 図表の活用（必要に応じて）

### 4. 保守性
- 更新日時を記録
- バージョン管理
- 変更履歴を残す

### 5. 一貫性
- 既存ドキュメントとスタイルを統一
- 用語の統一
- フォーマットの統一

## オプション機能

### 1. 既存ドキュメントの更新
既存のドキュメントファイルがある場合、上書きではなく更新を提案

### 2. 多言語対応
英語版ドキュメントも生成（オプション）

### 3. Mermaid図の生成
システム構成図、フローチャート、ER図などをMermaid形式で生成

### 4. 目次の自動生成
長いドキュメントには自動で目次を挿入

---

## 注意事項

- ドキュメントは `docs/` ディレクトリに保存
- 既存ファイルの上書き前に確認
- コードから自動生成する場合、コードの正確性を確認
- ドキュメントにはバージョン・更新日時を記載
- 機密情報（パスワード、APIキー等）は含めない
- 言語: 思考は英語、アウトプットは日本語

---

## ドキュメント管理のベストプラクティス

1. **定期的な更新**: コード変更時にドキュメントも更新
2. **レビュー**: ドキュメントもコードと同様にレビュー
3. **バージョン管理**: gitで管理
4. **アクセス性**: READMEから各ドキュメントへリンク
5. **実例の追加**: 具体的な使用例を含める

## 使用例

### プロジェクト初期セットアップ
```bash
/doc README.mdを作成
/doc APIドキュメントを作成
/doc セットアップガイドを作成
```

### 新機能追加時
```bash
# シンプルに
/design 有料プラン機能
/implement
/doc 有料プラン機能の仕様書を作成

# または専門家チームで一括
/team 有料プラン機能
/doc 有料プラン機能の仕様書を作成
```

### リリース前
```bash
/doc CHANGELOGを更新
/doc 運用ドキュメントを更新
```
