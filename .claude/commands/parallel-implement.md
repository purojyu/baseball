# 並列実装コマンド

タスクを3分割し、各タスクで3人の実装エージェントが並列実装、評価者がベストを選択、レビューで洗練、統合後に多段階レビューで品質を保証します。

## 実行フロー

### 1. タスク分割
設計または要件に基づいてタスクを3つに分割：

#### 分割例1: レイヤー別
- タスク1: Entity + Repository
- タスク2: Service
- タスク3: Controller + UI

#### 分割例2: 機能別
- タスク1: ユーザー登録
- タスク2: ログイン
- タスク3: プロフィール管理

#### 分割例3: フロント・バック分離
- タスク1: バックエンドAPI
- タスク2: フロントエンドUI
- タスク3: 統合テスト

**分割基準:**
- 各タスクが独立して実装可能
- 依存関係が最小限
- 工数が均等

---

### 2. タスク1の実装（設計パターンと同じ）

#### 2.1 並列実装（3人同時起動）
**Taskツールで3つのエージェントを並列起動:**

```
<Task> 実装者1A: タスク1をアプローチAで実装
  - オーソドックス、安定性重視
  - Spring Bootベストプラクティス
  - 実績のあるパターン

<Task> 実装者1B: タスク1をアプローチBで実装
  - パフォーマンス重視
  - 非同期処理活用
  - メモリ最適化

<Task> 実装者1C: タスク1をアプローチCで実装
  - 簡潔性・保守性重視
  - シンプルな実装
  - 可読性優先
```

各実装者は以下を実装：
- コーディング規約準拠（`docs/coding-standards.md`）
- アーキテクチャパターン準拠（`docs/baseball-project-architecture.md`）
- セキュリティ対策
- エラーハンドリング
- 適切なコメント

#### 2.2 評価・選択
評価エージェントが3つの実装を評価：

```
<Task> 評価者1: 3つの実装（1A, 1B, 1C）を評価し、ベストを選択
```

**評価基準:**
- ✅ コード品質
- ✅ パフォーマンス
- ✅ 保守性
- ✅ セキュリティ
- ✅ テスタビリティ
- ✅ 可読性
- ✅ 規約準拠

**スコアリング:**
各観点を10点満点で評価し、合計スコアで判定

#### 2.3 レビュー・洗練
レビューエージェントが選択された実装を精査：

```
<Task> レビュー者1: タスク1のベスト実装をレビュー・修正
```

**レビュー観点:**
- コーディング規約準拠
- アーキテクチャ整合性
- セキュリティ脆弱性（XSS、SQLインジェクション等）
- エラーハンドリング
- パフォーマンス
- エッジケース考慮

**修正プロセス:**
1. 問題点を指摘
2. 改善案を提示
3. 実装を修正
4. 再レビュー
5. 問題がなくなるまで繰り返し（最大3回）

#### 2.4 タスク1完成

---

### 3. タスク2の実装
タスク1と全く同じフロー：
- 並列実装（実装者2A, 2B, 2C）
- 評価・選択（評価者2）
- レビュー・洗練（レビュー者2、最大3回修正）

---

### 4. タスク3の実装
タスク1と全く同じフロー：
- 並列実装（実装者3A, 3B, 3C）
- 評価・選択（評価者3）
- レビュー・洗練（レビュー者3、最大3回修正）

---

### 5. 統合

3つのタスクの実装を統合:

```
<Task> 統合担当: 3つのタスクを統合し、動作確認
```

#### 統合作業
- ファイルのマージ
- インターフェース調整
- 依存関係解決
- 統合テスト
- ビルド確認

---

### 6. 統合レビュー

統合後のコード全体をレビュー:

```
<Task> 統合レビュー者: 統合されたコード全体をレビュー
```

#### レビュー観点
- 各部分の整合性
- データフローの正確性
- 全体的なアーキテクチャ
- 統合時のバグ
- インターフェースの一貫性

---

### 7. 最終レビュー

別の視点で最終チェック:

```
<Task> 最終レビュー者: 完成したコードを最終レビュー
```

#### 最終チェック
- プロダクション準備度
- ドキュメント完備
- テストカバレッジ
- デプロイ可能性
- セキュリティ最終確認

---

### 8. 完成報告

以下を含むレポート:
- 実装したファイル一覧
- 各タスクの実装内容
- 評価結果
- レビュー結果
- 統合結果
- 次のステップ

## エージェント数と実行順序

### 起動されるエージェント
1. **タスク1フェーズ**: 実装者1A, 1B, 1C（並列3人）→ 評価者1 → レビュー者1
2. **タスク2フェーズ**: 実装者2A, 2B, 2C（並列3人）→ 評価者2 → レビュー者2
3. **タスク3フェーズ**: 実装者3A, 3B, 3C（並列3人）→ 評価者3 → レビュー者3
4. **統合フェーズ**: 統合担当 → 統合レビュー者 → 最終レビュー者

**合計: 18エージェント**

### 実行順序の特徴
- タスク1, 2, 3は**順次実行**（依存関係があるため）
- 各タスク内の3人の実装者は**並列実行**
- 評価とレビューは選択後に**順次実行**

## 品質保証レベル

### 🌟🌟🌟🌟 高品質

このワークフローは以下を保証:

1. **多様な実装案** - 各タスクで3つの異なるアプローチ
2. **客観的評価** - 独立した評価者が選択
3. **複数回レビュー** - 各タスク3回 + 統合1回 + 最終1回
4. **段階的品質向上** - タスクごとに洗練
5. **全体整合性** - 統合レビューで確認
6. **最終チェック** - 別の視点で最終確認
