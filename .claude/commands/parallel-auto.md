# 並列自動実装コマンド

要件から完成まで、並列設計・並列実装・多段階レビューを全自動で実行します。

## 概要

このコマンドは `/parallel-design` と `/parallel-implement` を組み合わせた完全自動化ワークフローです。

## 全体ワークフロー

```
要件入力
   ↓
━━━━━━━━━━━━━━━━━━━━━
フェーズ1: 並列設計
━━━━━━━━━━━━━━━━━━━━━
   ↓
設計者A 設計者B 設計者C（並列）
   ↓
評価者（ベスト選択）
   ↓
レビュー者（修正繰り返し）
   ↓
設計完成
   ↓
━━━━━━━━━━━━━━━━━━━━━
フェーズ2: タスク分割
━━━━━━━━━━━━━━━━━━━━━
   ↓
タスク1 タスク2 タスク3
   ↓
━━━━━━━━━━━━━━━━━━━━━
フェーズ3: 並列実装
━━━━━━━━━━━━━━━━━━━━━
   ↓
各タスクで3人が並列実装（計9人）
   ↓
各タスクで評価者がベスト選択（3回）
   ↓

   ↓
━━━━━━━━━━━━━━━━━━━━━
フェーズ4: 統合・最終レビュー
━━━━━━━━━━━━━━━━━━━━━
   ↓
統合
   ↓
統合レビュー者
   ↓
最終レビュー者
   ↓
━━━━━━━━━━━━━━━━━━━━━
フェーズ5: テスト・ドキュメント
━━━━━━━━━━━━━━━━━━━━━
   ↓
簡易テスト実行
   ↓
ドキュメント生成
   ↓
完成報告
```

## 実行フロー

### フェーズ1: 並列設計（`/parallel-design`と同じ）

#### 1.1 要件確認
- ユーザーから要件を受け取る
- 不明点があれば質問

#### 1.2 並列設計（3人）
```
<Task> 設計者A: アーキテクチャ重視の設計
<Task> 設計者B: パフォーマンス重視の設計
<Task> 設計者C: 保守性重視の設計
```

#### 1.3 評価・選択
```
<Task> 評価者: 3つの設計案を評価し、ベスト選択
```

#### 1.4 レビュー・洗練
```
<Task> レビュー者: 設計をレビュー・修正（最大3回）
```

#### 1.5 設計承認
ユーザーに設計を提示し、承認を得る（y/n）

---

### フェーズ2: タスク分割

設計に基づいてタスクを3つに分割:
- 各タスクが独立して実装可能
- 依存関係が最小限
- 工数が均等

---

### フェーズ3: 並列実装（`/parallel-implement`と同じ）

#### 3.1 タスク1の並列実装（3人）
```
<Task> 実装者1A: タスク1をアプローチAで実装
<Task> 実装者1B: タスク1をアプローチBで実装
<Task> 実装者1C: タスク1をアプローチCで実装
```

#### 3.2 タスク1の評価
```
<Task> 評価者1: 3つの実装を評価し、ベスト選択
```

#### 3.3 タスク1のレビュー
```
<Task> レビュー者1: ベスト実装をレビュー・修正
```

#### 3.4 タスク2、タスク3も同様に実行

---

### フェーズ4: 統合・最終レビュー

#### 4.1 統合
```
<Task> 統合担当: 3つのタスクを統合
```

#### 4.2 統合レビュー
```
<Task> 統合レビュー者: 統合されたコード全体をレビュー
```

#### 4.3 最終レビュー
```
<Task> 最終レビュー者: 別の視点で最終チェック
```

---

### フェーズ5: テスト・ドキュメント

#### 5.1 簡易テスト実行
```
<Task> テスト担当: /quick-test を実行
```

- コンパイル確認
- ビルド確認
- 簡易動作確認

#### 5.2 ドキュメント生成
```
<Task> ドキュメント担当: /doc を実行
```

- 機能仕様書
- APIドキュメント（API追加の場合）
- 実装ドキュメント

---

### フェーズ6: 完成報告

以下を含む包括的なレポート:

## エージェント数と実行時間

### 起動されるエージェント数
- 設計者: 3人
- 設計評価者: 1人
- 設計レビュー者: 1人
- 実装者: 9人（3タスク × 3人）
- 実装評価者: 3人（各タスク1人）
- 実装レビュー者: 3人（各タスク1人）
- 統合担当: 1人
- 統合レビュー者: 1人
- 最終レビュー者: 1人
- テスト担当: 1人
- ドキュメント担当: 1人

**合計: 最大25エージェント**

### 実行時間の目安
- 小規模機能: 20-30分
- 中規模機能: 30-60分
- 大規模機能: 60-120分

※並列実行のため、単独実行より大幅に高速

## 品質保証レベル

### 🌟🌟🌟🌟🌟 最高品質

このワークフローは以下を保証:

1. **多様な設計案** - 3つの異なる視点
2. **客観的評価** - 独立した評価者
3. **複数回レビュー** - 設計1回、各実装3回、統合1回、最終1回
4. **並列実装** - 各タスクで3つの実装から最適を選択
5. **統合検証** - 部分最適ではなく全体最適
6. **多段階チェック** - 個別→統合→最終の3段階
7. **自動テスト** - 実装後すぐに動作確認
8. **ドキュメント完備** - 実装と同時にドキュメント生成

## 他のコマンドとの比較

| コマンド | エージェント数 | 設計 | 実装 | レビュー回数 | 品質 | 速度 |
|---------|--------------|------|------|-------------|------|------|
| `/implement` | 1 | ❌ | ✅ | 0 | ⭐⭐ | 最速 |
| `/auto-implement` | 1 | ✅ | ✅ | 1 | ⭐⭐⭐ | 速い |
| `/parallel-design` | 5 | ✅ | ❌ | 1 | ⭐⭐⭐⭐ | 中 |
| **`/team`** | **10** | **✅** | **✅** | **3（多角的）** | **⭐⭐⭐⭐** | **中** |
| `/parallel-implement` | 20 | ❌ | ✅ | 6 | ⭐⭐⭐⭐ | 遅い |
| `/parallel-auto` | 25 | ✅ | ✅ | 7 | ⭐⭐⭐⭐⭐ | 最遅 |

### `/team` vs `/parallel-auto` の違い
- **`/team`**: 10人の専門家が役割分担（効率的・実践的）
- **`/parallel-auto`**: 25人で競わせて最良を選択（網羅的・最高品質）

## 注意事項

- **実行時間**: 大規模な並列実行のため時間がかかります
- **コスト**: 多数のエージェントを起動するためトークン消費量が多い
- **承認ポイント**: 設計完了時に1回承認が必要
- **中断**: 途中で問題が発生した場合は報告し、対処方法を提案
- **言語**: 思考は英語、アウトプットは日本語

---

## ワークフロー制御

### 自動継続
基本的には全フェーズを自動で実行しますが、以下のタイミングでユーザー確認が入ります:

1. **設計完了時**: 設計内容の承認（y/n）
2. **重大な問題発生時**: 対処方法の確認

### スキップオプション（将来的に実装可能）
```
/parallel-auto --skip-design   # 設計をスキップ
/parallel-auto --skip-test     # テストをスキップ
/parallel-auto --skip-doc      # ドキュメントをスキップ
```
